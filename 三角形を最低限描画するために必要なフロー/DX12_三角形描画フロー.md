# DirectX 12 三角形描画までの最短フロー（細分化版）

Microsoft 公式サンプル **D3D12HelloTriangle** を最低限まで削った手順。
1つの .cpp と 1つの .hlsl で完結させる前提。

> 方針：「動く最小構成」を最優先。マルチフレーム並列・アダプタ選択・リサイズ対応などは**全部あと回し**。
> 各ステップの ✅ は「ここで一度ビルド・実行して確認する」ポイント。小さく作って毎回動かす。

---

## 全体像

```
Phase 0  準備
  0-1 プロジェクト作成 → 0-2 設定 → 0-3 ヘッダ/ライブラリ → 0-4 エラーチェック → 0-5 ComPtr
Phase 1  ウィンドウ
  1-1 WndProc → 1-2 クラス登録 → 1-3 サイズ計算 → 1-4 作成/表示 → 1-5 メッセージループ   ✅
Phase 2  DX12 初期化
  2-1 デバッグレイヤー → 2-2 Factory → 2-3 Device                                        ✅
  2-4 CommandQueue                                                                      ✅
  2-5 SwapChain 設定 → 2-6 作成 → 2-7 変換 → 2-8 frameIndex                              ✅
  2-9 RTV ヒープ → 2-10 増分サイズ → 2-11 バックバッファ取得 + RTV 作成                    ✅
  2-12 CommandAllocator → 2-13 CommandList → 2-14 Close                                 ✅
  2-15 Fence → 2-16 Event → 2-17 WaitForGPU 関数                                         ✅
Phase 3  画面クリア（中間ゴール）
  3-1 Reset → 3-2 バリア → 3-3 RTV ハンドル → 3-4 セット/クリア → 3-5 バリア
  → 3-6 Close → 3-7 Execute → 3-8 Present → 3-9 Wait                                    ✅ 単色画面
Phase 4  描画の準備
  4-1 ルートシグネチャ（4-1-1〜4-1-3）                                                     ✅
  4-2 HLSL 作成 → 4-3 コンパイル                                                          ✅
  4-4 入力レイアウト → 4-5 PSO 設定 → 4-6 PSO 作成                                        ✅
  4-7 頂点構造体 → 4-8 頂点データ → 4-9 バッファ作成 → 4-10 書き込み → 4-11 ビュー         ✅
  4-12 ビューポート → 4-13 シザー
Phase 5  三角形（ゴール）
  5-1 Reset を PSO 付きに → 5-2 ルートシグネチャ/ビューポート/シザー → 5-3 IA 設定 → 5-4 Draw ✅ 三角形
Phase 6  終了処理
  6-1 GPU 待ち → 6-2 ハンドル解放
```

GPU に仕事をさせる基本の流れは常にこれ：
**CommandList に命令を書く → Close → Queue に投げる → Fence で終わりを待つ**

# Phase 0 準備

### 0-1 プロジェクト作成
- Visual Studio →「空のプロジェクト」（C++）
- `main.cpp` を追加

### 0-2 プロジェクト設定
- ツールバーの構成を **x64** にする
- プロジェクトのプロパティ → リンカー → システム → サブシステム：**Windows**
- エントリポイントは `WinMain`（`main` ではない）
- ✅ 空の `WinMain`（`return 0;` だけ）でビルドが通る

### 0-3 ヘッダとライブラリ
| 種類 | 中身 | 用途 |
|---|---|---|
| ヘッダ | `<windows.h>` | Win32 |
| ヘッダ | `<d3d12.h>` | DX12 本体 |
| ヘッダ | `<dxgi1_6.h>` | SwapChain・Factory |
| ヘッダ | `<d3dcompiler.h>` | シェーダコンパイル |
| ヘッダ | `<wrl.h>` | ComPtr |
| ライブラリ | `d3d12.lib` | |
| ライブラリ | `dxgi.lib` | |
| ライブラリ | `d3dcompiler.lib` | |

- ライブラリは `#pragma comment(lib, "d3d12.lib")` の形で書くのが最速（プロジェクト設定を触らずに済む）
- ✅ ビルドが通る（リンクエラーが出ない）

### 0-4 （任意）d3dx12.h
- 公式ヘルパー。GitHub `microsoft/DirectX-Headers` の `include/directx/` をフォルダごとコピー
- **このフローは d3dx12 なしで書ける値を全部記載している**。まずは使わずに書くと、各構造体の中身が理解できる

### 0-5 エラーチェックの仕組み
- DX12 の関数はほぼ `HRESULT` を返す
- `FAILED(hr)` のときに「止まる」関数かマクロを 1 つ作る
  - 例：メッセージボックスを出す / `__debugbreak()` でブレーク / 例外を投げる
- **これを最初に作らないと、どこで壊れたか分からなくなる**
- ✅ わざと失敗する HRESULT（`E_FAIL`）を渡して止まることを確認

### 0-6 ComPtr の使い方を把握
- `Microsoft::WRL::ComPtr<T>`：スコープを抜けると自動で `Release()` される
- 作成系関数には `IID_PPV_ARGS(&ptr)` を渡す（型 ID とポインタを同時に渡すマクロ）
- 生ポインタが欲しいとき：`ptr.Get()`
- 別のインターフェースへ変換：`ptr.As(&other)`

# Phase 1 Win32 ウィンドウ

### 1-1 ウィンドウプロシージャ（WndProc）を書く
- シグネチャ：`LRESULT CALLBACK WndProc(HWND, UINT, WPARAM, LPARAM)`
- `WM_DESTROY` が来たら `PostQuitMessage(0)` して 0 を返す
- それ以外は `DefWindowProc` に任せる

### 1-2 ウィンドウクラスを登録
- `WNDCLASSEX` を 0 初期化して設定
  - `cbSize = sizeof(WNDCLASSEX)`
  - `style = CS_HREDRAW | CS_VREDRAW`
  - `lpfnWndProc = WndProc`
  - `hInstance = WinMain の引数`
  - `hCursor = LoadCursor(nullptr, IDC_ARROW)`
  - `lpszClassName = 好きな名前（L"..."）`
- `RegisterClassEx(&wc)`

### 1-3 ウィンドウサイズを計算
- 描画したいサイズ（例：1280×720）を `RECT` に入れる
- `AdjustWindowRect(&rect, WS_OVERLAPPEDWINDOW, FALSE)`
  - タイトルバーや枠の分を足してくれる。これをしないと**描画領域が指定より小さくなる**

### 1-4 ウィンドウ作成・表示
- `CreateWindow(クラス名, タイトル, WS_OVERLAPPEDWINDOW, CW_USEDEFAULT, CW_USEDEFAULT, rect.right - rect.left, rect.bottom - rect.top, nullptr, nullptr, hInstance, nullptr)`
- 戻り値 `hwnd` を保存（SwapChain 作成で使う）
- `ShowWindow(hwnd, nCmdShow)`

### 1-5 メッセージループ
```
MSG msg = {}
while (msg.message != WM_QUIT) {
    if (PeekMessage(&msg, nullptr, 0, 0, PM_REMOVE)) {
        TranslateMessage(&msg)
        DispatchMessage(&msg)
    } else {
        // ここで毎フレームの描画（Phase 3 以降）
    }
}
```
- `GetMessage` はメッセージが来るまで止まる → ゲームでは止まらない `PeekMessage` を使う

✅ **確認**：空のウィンドウが出て、× で閉じるとプロセスが終了する（タスクマネージャーに残らない）

# Phase 2 DX12 初期化

> Phase 2 の処理は全部「初期化関数」にまとめ、1-4 と 1-5 の間で呼ぶ。

### 2-1 デバッグレイヤー（`_DEBUG` のときだけ）
- `ComPtr<ID3D12Debug> debug`
- `D3D12GetDebugInterface(IID_PPV_ARGS(&debug))`
- `debug->EnableDebugLayer()`
- **Device を作る前に呼ぶ**（後だと効かない）

### 2-2 DXGI Factory
- `CreateDXGIFactory2(flags, IID_PPV_ARGS(&factory))`
  - デバッグ時 `flags = DXGI_CREATE_FACTORY_DEBUG`、リリース時 0
- Factory = SwapChain などを作る工場

### 2-3 Device
- `D3D12CreateDevice(nullptr, D3D_FEATURE_LEVEL_11_0, IID_PPV_ARGS(&device))`
  - `nullptr` = 既定の GPU。最低限ならアダプタ選択は不要
- Device = GPU のリソース（バッファ・ヒープ等）を作る窓口

✅ **確認**：起動しても落ちない。出力ウィンドウにエラーがない

### 2-4 CommandQueue
- `D3D12_COMMAND_QUEUE_DESC desc = {}`
  - `Type = D3D12_COMMAND_LIST_TYPE_DIRECT`（描画もできる汎用キュー）
  - `Flags = D3D12_COMMAND_QUEUE_FLAG_NONE`
- `device->CreateCommandQueue(&desc, IID_PPV_ARGS(&commandQueue))`
- CommandQueue = GPU への命令の受付窓口

✅ **確認**：落ちない

### 2-5 SwapChain の設定を書く
`DXGI_SWAP_CHAIN_DESC1 desc = {}`

| 項目 | 値 | 意味 |
|---|---|---|
| Width / Height | 1280 / 720 | 1-3 で決めた描画サイズ |
| Format | `DXGI_FORMAT_R8G8B8A8_UNORM` | 1 ピクセル = RGBA 各 8bit |
| SampleDesc.Count | 1 | MSAA なし |
| BufferUsage | `DXGI_USAGE_RENDER_TARGET_OUTPUT` | 描画先として使う |
| BufferCount | **2** | 表と裏（Flip モデルは最低 2） |
| SwapEffect | `DXGI_SWAP_EFFECT_FLIP_DISCARD` | DX12 で推奨される方式 |

### 2-6 SwapChain を作成
- `ComPtr<IDXGISwapChain1> swapChain1`
- `factory->CreateSwapChainForHwnd(commandQueue.Get(), hwnd, &desc, nullptr, nullptr, &swapChain1)`
  - ⚠️ 第 1 引数は **Device ではなく CommandQueue**（DX11 との違い）
- （任意）`factory->MakeWindowAssociation(hwnd, DXGI_MWA_NO_ALT_ENTER)`：Alt+Enter のフルスクリーン切替を無効化

### 2-7 SwapChain3 に変換
- `swapChain1.As(&swapChain)`（`swapChain` は `IDXGISwapChain3` 以上）
- 理由：次の `GetCurrentBackBufferIndex` は SwapChain3 以降にしかない

### 2-8 現在のバックバッファ番号を取得
- `frameIndex = swapChain->GetCurrentBackBufferIndex()`
- 0 か 1。「今描くべきバッファ」の番号

✅ **確認**：ウィンドウが黒くなる（SwapChain がウィンドウに紐づいた証拠。真っ黒でなく白いままでも、落ちなければ OK）

### 2-9 RTV 用ディスクリプタヒープ
- ディスクリプタ＝「このリソースをこう使う」という GPU 向けの説明書
- ヒープ＝それを並べる配列
- `D3D12_DESCRIPTOR_HEAP_DESC desc = {}`
  - `Type = D3D12_DESCRIPTOR_HEAP_TYPE_RTV`
  - `NumDescriptors = 2`（バックバッファの枚数）
  - `Flags = D3D12_DESCRIPTOR_HEAP_FLAG_NONE`
- `device->CreateDescriptorHeap(&desc, IID_PPV_ARGS(&rtvHeap))`

### 2-10 ディスクリプタ 1 個分のサイズを取得
- `rtvDescriptorSize = device->GetDescriptorHandleIncrementSize(D3D12_DESCRIPTOR_HEAP_TYPE_RTV)`
- GPU によってサイズが違うので、決め打ちせず必ず取得する

### 2-11 バックバッファを取得して RTV を作る
```
handle = rtvHeap->GetCPUDescriptorHandleForHeapStart()
for i = 0..1:
    swapChain->GetBuffer(i, IID_PPV_ARGS(&renderTargets[i]))
    device->CreateRenderTargetView(renderTargets[i].Get(), nullptr, handle)
    handle.ptr += rtvDescriptorSize      // 次の枠へ
```
- `CreateRenderTargetView` の第 2 引数 `nullptr` = リソースの設定をそのまま使う

✅ **確認**：落ちない、エラーなし

### 2-12 CommandAllocator
- `device->CreateCommandAllocator(D3D12_COMMAND_LIST_TYPE_DIRECT, IID_PPV_ARGS(&commandAllocator))`
- = 命令を書き込む**メモリ領域**

### 2-13 CommandList
- `device->CreateCommandList(0, D3D12_COMMAND_LIST_TYPE_DIRECT, commandAllocator.Get(), nullptr, IID_PPV_ARGS(&commandList))`
  - 第 1 引数 0 = GPU が 1 枚の場合
  - 第 4 引数 nullptr = 初期 PSO なし（Phase 5 で変わるのは Reset 時だけ）
- = 命令を**書く道具**。書いた内容は Allocator のメモリに溜まる

### 2-14 すぐに Close
- `commandList->Close()`
- 作成直後は「記録中」。毎フレーム先頭で Reset するには「閉じた」状態である必要がある

✅ **確認**：落ちない、エラーなし

### 2-15 Fence
- `device->CreateFence(0, D3D12_FENCE_FLAG_NONE, IID_PPV_ARGS(&fence))`
- `fenceValue = 1`
- Fence = GPU 側に置くカウンタ。「GPU がどこまで仕事を終えたか」を数字で表す

### 2-16 Event
- `fenceEvent = CreateEvent(nullptr, FALSE, FALSE, nullptr)`
- `nullptr` が返ったら失敗
- Event = CPU を「起こしてもらうまで寝かせる」ための OS の仕組み

### 2-17 WaitForGPU 関数を作る
```
void WaitForGPU():
    value = fenceValue
    commandQueue->Signal(fence.Get(), value)   // GPU に「ここまで終わったら fence を value にして」と頼む
    fenceValue++
    if fence->GetCompletedValue() < value:     // まだ終わってない？
        fence->SetEventOnCompletion(value, fenceEvent)   // 終わったら Event を鳴らして
        WaitForSingleObject(fenceEvent, INFINITE)         // 鳴るまで CPU は寝る
    frameIndex = swapChain->GetCurrentBackBufferIndex()   // 次に描くバッファを更新
```
- 最低限構成では**毎フレームこれで GPU の完了を待つ**。遅いが一番単純で安全

✅ **確認**：初期化の最後で 1 回呼んで、固まらずに戻ってくる

# Phase 3 画面クリア（中間ゴール）

> Phase 3 の処理は「描画関数」にまとめ、1-5 のループの `else` 内で毎フレーム呼ぶ。

### 3-1 記録開始
- `commandAllocator->Reset()`：前フレームの命令メモリを空にする（**GPU が使い終わってから**でないとダメ → 前フレームで WaitForGPU 済みなので OK）
- `commandList->Reset(commandAllocator.Get(), nullptr)`：記録開始

### 3-2 バリア：PRESENT → RENDER_TARGET
`D3D12_RESOURCE_BARRIER barrier = {}`

| 項目 | 値 |
|---|---|
| Type | `D3D12_RESOURCE_BARRIER_TYPE_TRANSITION` |
| Flags | `D3D12_RESOURCE_BARRIER_FLAG_NONE` |
| Transition.pResource | `renderTargets[frameIndex].Get()` |
| Transition.StateBefore | `D3D12_RESOURCE_STATE_PRESENT` |
| Transition.StateAfter | `D3D12_RESOURCE_STATE_RENDER_TARGET` |
| Transition.Subresource | `D3D12_RESOURCE_BARRIER_ALL_SUBRESOURCES` |

- `commandList->ResourceBarrier(1, &barrier)`
- 意味：「このバッファを表示用から描画先に切り替える」

### 3-3 今のバックバッファの RTV ハンドルを計算
- `rtvHandle = rtvHeap->GetCPUDescriptorHandleForHeapStart()`
- `rtvHandle.ptr += frameIndex * rtvDescriptorSize`

### 3-4 描画先をセットしてクリア
- `commandList->OMSetRenderTargets(1, &rtvHandle, FALSE, nullptr)`
  - 最後の `nullptr` = 深度バッファなし
- `float clearColor[] = { R, G, B, A }`（0.0〜1.0）
- `commandList->ClearRenderTargetView(rtvHandle, clearColor, 0, nullptr)`

### 3-5 バリア：RENDER_TARGET → PRESENT
- 3-2 と同じ構造体で、Before と After を逆にする
- `commandList->ResourceBarrier(1, &barrier)`

### 3-6 記録終了
- `commandList->Close()`

### 3-7 GPU に送る
- `ID3D12CommandList* lists[] = { commandList.Get() }`
- `commandQueue->ExecuteCommandLists(1, lists)`

### 3-8 画面に表示
- `swapChain->Present(1, 0)`
  - 第 1 引数 1 = VSync を待つ（60Hz なら 60FPS に固定）

### 3-9 GPU の完了を待つ
- `WaitForGPU()`（frameIndex もここで更新される）

✅ **確認**：ウィンドウが指定色で塗りつぶされる 🎉
✅ **確認**：出力ウィンドウに `D3D12 ERROR` が出ていない
✅ **確認**：色を変えてビルドし直すと反映される

# Phase 4 描画の準備（すべて初期化関数に追加）

## ルートシグネチャ

シェーダに渡すリソース（定数・テクスチャ等）の**一覧表**。三角形だけなら中身は空。

### 4-1-1 設定を書く
`D3D12_ROOT_SIGNATURE_DESC desc = {}`
- `NumParameters = 0`、`pParameters = nullptr`
- `NumStaticSamplers = 0`、`pStaticSamplers = nullptr`
- `Flags = D3D12_ROOT_SIGNATURE_FLAG_ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT`（頂点バッファを使うのに必要）

### 4-1-2 バイナリにシリアライズ
- `ComPtr<ID3DBlob> signatureBlob, errorBlob`
- `D3D12SerializeRootSignature(&desc, D3D_ROOT_SIGNATURE_VERSION_1, &signatureBlob, &errorBlob)`
- 失敗時は `errorBlob` の中身（文字列）を `OutputDebugStringA` で出す

### 4-1-3 作成
- `device->CreateRootSignature(0, signatureBlob->GetBufferPointer(), signatureBlob->GetBufferSize(), IID_PPV_ARGS(&rootSignature))`

✅ **確認**：落ちない、エラーなし

## シェーダ

### 4-2 shaders.hlsl を作成
- 置き場所：**プロジェクトフォルダ（.vcxproj と同じ場所）**。VS から実行したときの作業ディレクトリがここだから
- ファイルのプロパティ →「ビルドから除外」を **はい**（VS が勝手にコンパイルしてエラーになるのを防ぐ）
- 中身の構造：
  - 入力構造体：`float3 pos : POSITION` / `float4 color : COLOR`
  - 出力構造体：`float4 pos : SV_POSITION` / `float4 color : COLOR`
  - `VSMain(入力)`：`pos` を `float4(pos, 1.0)` にして出力、`color` はそのまま渡す
  - `PSMain(出力構造体)`：`color` を返す。戻り値のセマンティクスは `SV_TARGET`

### 4-3 コンパイル
- フラグ：デバッグ時 `D3DCOMPILE_DEBUG | D3DCOMPILE_SKIP_OPTIMIZATION`、リリース時 0
- 頂点シェーダ：
  `D3DCompileFromFile(L"shaders.hlsl", nullptr, nullptr, "VSMain", "vs_5_0", flags, 0, &vsBlob, &errorBlob)`
- ピクセルシェーダ：
  `D3DCompileFromFile(L"shaders.hlsl", nullptr, nullptr, "PSMain", "ps_5_0", flags, 0, &psBlob, &errorBlob)`
- 失敗時は `errorBlob` を `OutputDebugStringA` で出す（**HLSL の文法エラーはここでしか分からない**）
- よくある失敗：`HRESULT` が「ファイルが見つからない」→ 作業ディレクトリと .hlsl の場所がずれている

✅ **確認**：わざと HLSL に文法エラーを入れて、出力ウィンドウにエラー行が出ることを確認 → 直してエラーなし

## PSO（パイプラインステート）

描画の設定を**全部まとめて 1 つに固めたもの**。

### 4-4 入力レイアウト（頂点 1 個の中身の説明書）
`D3D12_INPUT_ELEMENT_DESC inputLayout[2]`

| SemanticName | SemanticIndex | Format | InputSlot | AlignedByteOffset | InputSlotClass | InstanceDataStepRate |
|---|---|---|---|---|---|---|
| `"POSITION"` | 0 | `DXGI_FORMAT_R32G32B32_FLOAT` | 0 | 0 | `D3D12_INPUT_CLASSIFICATION_PER_VERTEX_DATA` | 0 |
| `"COLOR"` | 0 | `DXGI_FORMAT_R32G32B32A32_FLOAT` | 0 | 12 | `D3D12_INPUT_CLASSIFICATION_PER_VERTEX_DATA` | 0 |

- オフセット 12 = float × 3 = 12 バイト（POSITION の後ろに COLOR がある）
- SemanticName は HLSL の `: POSITION` `: COLOR` と**文字列で一致**させる

### 4-5 PSO の設定を書く
`D3D12_GRAPHICS_PIPELINE_STATE_DESC desc = {}`（**必ず 0 初期化**）

**基本**

| 項目 | 値 |
|---|---|
| pRootSignature | `rootSignature.Get()` |
| VS | `{ vsBlob->GetBufferPointer(), vsBlob->GetBufferSize() }` |
| PS | `{ psBlob->GetBufferPointer(), psBlob->GetBufferSize() }` |
| InputLayout | `{ inputLayout, 2 }` |
| PrimitiveTopologyType | `D3D12_PRIMITIVE_TOPOLOGY_TYPE_TRIANGLE` |
| NumRenderTargets | 1 |
| RTVFormats[0] | `DXGI_FORMAT_R8G8B8A8_UNORM`（2-5 と一致させる） |
| SampleDesc.Count | 1 |
| SampleMask | `UINT_MAX` |

**RasterizerState**（三角形をピクセルにする段階）

| 項目 | 値 |
|---|---|
| FillMode | `D3D12_FILL_MODE_SOLID` |
| CullMode | `D3D12_CULL_MODE_BACK`（うまく出ないときは `NONE` で切り分け） |
| FrontCounterClockwise | `FALSE`（= 時計回りが表） |
| DepthClipEnable | `TRUE` |
| その他 | 0 / FALSE |

**BlendState**（色の混ぜ方）

| 項目 | 値 |
|---|---|
| AlphaToCoverageEnable | FALSE |
| IndependentBlendEnable | FALSE |
| RenderTarget[0].BlendEnable | FALSE |
| RenderTarget[0].LogicOpEnable | FALSE |
| RenderTarget[0].RenderTargetWriteMask | `D3D12_COLOR_WRITE_ENABLE_ALL` ⚠️ |

- ⚠️ WriteMask を 0 のままにすると**何も描かれない**

**DepthStencilState**

| 項目 | 値 |
|---|---|
| DepthEnable | FALSE |
| StencilEnable | FALSE |

### 4-6 PSO を作成
- `device->CreateGraphicsPipelineState(&desc, IID_PPV_ARGS(&pipelineState))`
- 失敗したらほぼ設定ミス → 出力ウィンドウのデバッグレイヤーのメッセージがどの項目か教えてくれる

✅ **確認**：落ちない、エラーなし

## 頂点バッファ

### 4-7 頂点構造体を定義
- `struct Vertex { float position[3]; float color[4]; };`（または DirectXMath の `XMFLOAT3` / `XMFLOAT4`）
- サイズ = 12 + 16 = 28 バイト。4-4 の入力レイアウトと**並び・サイズが一致**していること

### 4-8 頂点データ（3 個）
| 頂点 | 位置 (x, y, z) | 色 (r, g, b, a) |
|---|---|---|
| 上 | 0.0, 0.5, 0.0 | 1, 0, 0, 1（赤） |
| 右下 | 0.5, -0.5, 0.0 | 0, 1, 0, 1（緑） |
| 左下 | -0.5, -0.5, 0.0 | 0, 0, 1, 1（青） |

- 座標は画面中央が (0,0)、左右・上下が -1〜1
- ⚠️ 並び順は**時計回り**（上 → 右下 → 左下）。逆だと裏面扱いで消える

### 4-9 バッファ（GPU メモリ）を作成
**ヒープ設定** `D3D12_HEAP_PROPERTIES heapProps = {}`
- `Type = D3D12_HEAP_TYPE_UPLOAD`（CPU から直接書ける。本番では遅いが最低限ならこれで OK）

**リソース設定** `D3D12_RESOURCE_DESC resDesc = {}`

| 項目 | 値 |
|---|---|
| Dimension | `D3D12_RESOURCE_DIMENSION_BUFFER` |
| Width | `sizeof(頂点配列)`（= 28 × 3 = 84） |
| Height | 1 |
| DepthOrArraySize | 1 |
| MipLevels | 1 |
| Format | `DXGI_FORMAT_UNKNOWN` |
| SampleDesc.Count | 1 |
| Layout | `D3D12_TEXTURE_LAYOUT_ROW_MAJOR` |
| Flags | `D3D12_RESOURCE_FLAG_NONE` |

**作成**
- `device->CreateCommittedResource(&heapProps, D3D12_HEAP_FLAG_NONE, &resDesc, D3D12_RESOURCE_STATE_GENERIC_READ, nullptr, IID_PPV_ARGS(&vertexBuffer))`
  - Upload ヒープの初期状態は `GENERIC_READ` 固定

### 4-10 頂点データを書き込む
1. `D3D12_RANGE readRange = { 0, 0 }`（CPU からは読まない、という宣言）
2. `void* mapped; vertexBuffer->Map(0, &readRange, &mapped)` → GPU メモリの CPU 用アドレスがもらえる
3. `memcpy(mapped, 頂点配列, sizeof(頂点配列))`
4. `vertexBuffer->Unmap(0, nullptr)`

### 4-11 頂点バッファビュー
`D3D12_VERTEX_BUFFER_VIEW vertexBufferView`
- `BufferLocation = vertexBuffer->GetGPUVirtualAddress()`
- `StrideInBytes = sizeof(Vertex)`（頂点 1 個のサイズ）
- `SizeInBytes = sizeof(頂点配列)`（全体のサイズ）

✅ **確認**：落ちない、エラーなし

## ビューポートとシザー

### 4-12 ビューポート（描画範囲）
`D3D12_VIEWPORT viewport`
- `TopLeftX = 0`、`TopLeftY = 0`
- `Width = 1280.0f`、`Height = 720.0f`
- `MinDepth = 0.0f`、`MaxDepth = 1.0f`

### 4-13 シザー矩形（切り抜き範囲）
`D3D12_RECT scissorRect`
- `left = 0`、`top = 0`、`right = 1280`、`bottom = 720`

# Phase 5 三角形（ゴール）— 描画関数を修正

### 5-1 Reset に PSO を渡す
- 3-1 の `commandList->Reset(commandAllocator.Get(), nullptr)` の `nullptr` を `pipelineState.Get()` に変更

### 5-2 ルートシグネチャ・ビューポート・シザーをセット（3-1 の直後）
- `commandList->SetGraphicsRootSignature(rootSignature.Get())`
- `commandList->RSSetViewports(1, &viewport)`
- `commandList->RSSetScissorRects(1, &scissorRect)`
- ⚠️ **ビューポートとシザーを忘れると何も描かれない**（よくある失敗 No.1）

### 5-3 入力アセンブラの設定（3-4 のクリアの後）
- `commandList->IASetPrimitiveTopology(D3D_PRIMITIVE_TOPOLOGY_TRIANGLELIST)`（頂点 3 つで三角形 1 つ）
- `commandList->IASetVertexBuffers(0, 1, &vertexBufferView)`

### 5-4 描画命令（5-3 の直後、3-5 のバリアの前）
- `commandList->DrawInstanced(3, 1, 0, 0)`
  - 頂点 3 個、インスタンス 1 個、開始頂点 0、開始インスタンス 0

### 最終的な描画関数の順番
```
3-1  allocator Reset / commandList Reset(PSO 付き)
5-2  ルートシグネチャ / ビューポート / シザー
3-2  バリア PRESENT → RENDER_TARGET
3-3  RTV ハンドル計算
3-4  OMSetRenderTargets / Clear
5-3  トポロジ / 頂点バッファ
5-4  DrawInstanced
3-5  バリア RENDER_TARGET → PRESENT
3-6  Close
3-7  Execute
3-8  Present
3-9  WaitForGPU
```

✅ **確認**：赤・緑・青のグラデーション三角形が表示される 🎉🎉

# Phase 6 終了処理

### 6-1 GPU の完了を待つ
- メッセージループを抜けた後に `WaitForGPU()`
- GPU が使っているリソースを先に解放すると**クラッシュ / デバッグレイヤーのエラー**になる

### 6-2 ハンドル解放
- `CloseHandle(fenceEvent)`
- ComPtr はスコープを抜けると自動解放（グローバルならプログラム終了時）

✅ **確認**：× で閉じたとき、出力ウィンドウにエラー・警告が出ない

## 何も表示されないときのチェックリスト

| # | 確認すること | 関係するステップ |
|---|---|---|
| 1 | 出力ウィンドウに `D3D12 ERROR` が出ていないか | 2-1 |
| 2 | ビューポート・シザーを設定しているか | 4-12, 4-13, 5-2 |

| 7 | シェーダのコンパイルエラーを `errorBlob` で確認したか | 4-3 |
| 8 | バリアの Before/After が正しいか | 3-2, 3-5 |
| 9 | Reset に PSO を渡しているか | 5-1 |

## 意図的に省いたもの（三角形の後にやること）

| 省いたもの | なぜ後で必要か |
|---|---|
| フレームごとの Allocator / Fence 値（ダブルバッファリング） | 毎フレーム GPU を待つと CPU と GPU が並列に動けず遅い |
| Default ヒープ + Upload ヒープ経由のコピー | Upload ヒープは GPU から読むのが遅い |
| アダプタ列挙（GetHardwareAdapter） | 複数 GPU の PC で正しい GPU を選ぶため |
| ウィンドウのリサイズ対応 | `ResizeBuffers` と RTV の作り直しが必要 |
| 深度バッファ | 3D で前後関係を正しく描くため |
| 定数バッファ + ルートパラメータ | 行列を渡して三角形を動かす・カメラを作るため |
| シェーダの事前コンパイル（.cso / DXC） | 起動時間短縮・SM6 の機能を使うため |
